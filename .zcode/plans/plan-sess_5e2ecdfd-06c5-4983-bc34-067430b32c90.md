# 从「赛道赛车」转向「开放世界驾驶」— 实施方案

## 一、结论先行

现有代码里**可复用的比需要重写的多**：车辆物理（Rapier 车辆控制器 + 摩擦圆 + 路面系统）、纸艺材质与场景生成、音频、追车相机、输入、调试面板全部原样保留。真正要改的是「一条闭合赛道」这个假设。

探查后发现两个好消息：
- `buildRibbon()` 本来就有 `closed` 参数（只是一直传 `true`）→ 开放路段改动很小。
- 地形走廊本来就用「到中心线的最近距离」决定挖空范围 → 换成「到**所有**路段的最近距离」就自然支持路网。

**关键简化：不需要写通用的路口铺装生成器。** 两条路的路面在路口处本来就重叠，已经是连续可行驶面；环岛直接用一条 `closed` 环形路段（现成能力）+ 中央抬高的实体岛解决。因此路口零新增几何类型。

## 二、第一区域（Region 1）具体内容

**范围**：约 10–14 km 路网，主题＝郊野 + 林地 + 村庄
**做法**：**把现有 1194 m 草甸环线并入路网**（它是一条已验证的闭合路段，直接贡献 1.2 km），再新增：

| 内容 | 说明 |
| --- | --- |
| 主干道 ~5 km | 双车道郊野公路，宽 9 m，大半径弯，长直道 |
| 林道 ~4 km | 窄 6 m，多弯、起伏，两侧密林，路面材质略不同（抓地略低） |
| 村道 ~2 km | 穿过村庄，窄 6 m，路口密 |
| 环岛 ×1 | 环形路段 + 中央纸艺岛（花坛/风车小塔） |
| 丁字口/十字口 ×3~4 | 两条路直接重叠连通 |
| 通往下一区的闸口 ×1 | 区域边界上留一个缺口，空气墙在那里断开 |
| 地标 | 现有大纸风车（郊野）+ 新增村口牌坊/水车 |

区域边界：矩形范围，四周一圈**不可见碰撞墙**；并在边界内侧加一条很淡的纸边脊线做视觉暗示（避免玩家以为撞到 bug）。撞墙时 HUD 提示「此区域尚未开放」。

## 三、架构改动

### 新增（`src/world/`）
- `types.ts` — `RegionConfig / RoadSegmentConfig / JunctionConfig / GateConfig / CollectibleConfig / TimeTrialConfig`
- `RoadSegment.ts` — 单条路（包装现有 Centerline，支持 `closed:false`）
- `RoadNetwork.ts` — 多路段 + 空间索引；`project(x,z)` 返回 `{segmentIndex,t,lateral,distance,halfWidth}`；跨全网的 `roadHeightAt()`
- `Region.ts` — 组装：路网几何 + 所有碰撞体 + 地形 + 区域边界碰撞 + 装饰 + 地标
- `catalog/meadowRegion.ts` — 第一区域数据（含把草甸环线并入）

### 改造
| 文件 | 改动 |
| --- | --- |
| `Centerline.ts` | 支持 `closed:false`：开放 Catmull-Rom（端点复制而非回绕）、切向/超高平滑在端点夹紧、`project` 返回段内 t |
| `RoadGeometry.ts` | 路段端点与路口附近的**护栏自动抑制**（否则护栏会横在路口中间挡路）；路口处跳过装饰 |
| `Terrain.ts` | 走廊高度与挖空判定改用「到全网最近路段距离」；其余算法不变 |
| `TrackView.ts` | 拆成 `RegionView`：路网渲染 + 按 biome 分组装饰 + 地标 |
| `validate.ts` | 新增路网校验：连通性（所有路段必须可达）、端点对齐容差、路段间距（避免非路口处重叠）、每个区域至少一个出口闸口 |
| `Game.ts` | 启动进开放世界而非单条赛道 |
| `Hud.ts` | 圈数/名次 → 收集进度 / 区域完成度 / 下一目标方位 |
| `Menu.ts` | 赛道卡 → 区域卡（含路网缩略图 + 完成度） |

### 保留不动
`Car` / `Drivetrain` / `VehicleSpec` / `PhysicsWorld` / `CollisionGroups` / `AudioEngine` / `PaperMaterials` / `Scenery` / `CarVisual` / `ChaseCamera` / `Input` / `DebugPanel`。现有 `RaceSession` 保留，供以后把草甸环线做成「环线计时赛」可选活动（不塞进主流程）。

### 新增玩法系统（`src/world/` + `src/save/`）
- `WorldSession.ts` — 自由驾驶状态、收集物拾取、计时挑战（起终点门 + 最佳成绩）、区域完成度计算
- `src/save/SaveGame.ts` — localStorage，含**版本号与损坏数据恢复**；存：已拾取收藏品、各挑战最佳成绩、已解锁区域、设置
- `src/ui/MapScreen.ts` — 全屏地图（路网、收藏品、挑战门、玩家、区域边界、完成度），按键 `Tab`
- 拾取品：纸风车碎片（旋转纸片）+ 拾取音效 + HUD 计数
- 计时挑战门：复用现有纸艺拱门视觉 + 现有时间格式化与记录逻辑

## 四、分阶段交付（每阶段结束都跑测试 + 浏览器验证 + 报告）

**S1 架构打通（先让你能开上多路口路网）**
开放曲线 Centerline → RoadNetwork（多路段 + 空间索引）→ 全网段碰撞 + 全网地形走廊 → 区域边界空气墙 → 调试可视化画出路网与边界。
验收：在一条约 3 km、含 1 个环岛的多路口路网上自由驾驶，能上环岛、撞到边界会被挡住、不穿模、不卡死。

**S2 区域内容补到 10–14 km**
草甸环线并入 + 郊野/林地/村道 + 村庄建筑群 + 地标 + 装饰按 biome 分组。
验收：路网连通性校验通过；全区域可完整驾驶；景观分区明确。

**S3 玩法与存档**
收集物 + 计时挑战门 + 区域完成度 + localStorage 存档（含损坏恢复）+ 地图界面 + HUD 改造。
验收：收集与挑战成绩重载后一致；完成度可复现。

**S4 打磨**
性能（分块合并/实例化）、材质细节、音效补充、文档更新。

## 五、需要你知道的取舍与风险

1. **路口处路肩/车道线会互相交叠**，我按纸艺风格接受这种「纸带叠在一起」的观感，但**护栏会在路口附近自动抑制**（这是功能必需，否则堵路）。如果你要求路口铺装完全干净，需要额外一轮做多边形裁剪，成本明显更高。
2. **10–14 km 手工控制点不现实**，我会用现有 `tools/track-lab.mjs` 程序化生成候选路线 + 数值校验（曲率/坡度/自交/连通性）再落地成显式控制点，保持可手工微调。
3. **每个区域的边界是矩形**，空气墙沿矩形布置并在闸口断开。跨区域连通靠闸口位置对齐，暂时只做「闸口存在 + 撞墙提示」，不做出无缝跨区流式加载。
4. 这是一次**产品方向变更**，我把现有「阶段二~五」计划替换为上表 S1–S4；原计划的 AI 对手仍然没做（开放世界里 AI 车流的优先级我会在 S3 之后单独跟你确认）。
5. 交付顺序上 S1 结束时路网还是「骨架级」的（几何正确、碰撞正确、但景观少），S2 才补景观——这样你能尽早开上车并判断方向对不对。

## 六、开工顺序

先做 S1：`src/world/types.ts` → `RoadNetwork.ts` → `Centerline` 开放曲线支持 → `Region.ts`（含空气墙）→ 调试可视化 → 用一条骨架路网在浏览器里开一圈验证。S1 通过后再进 S2。
